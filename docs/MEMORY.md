- inert placeholder links: keyed off `href` prefix (`http` → new tab + rel, else inert) instead of icon type, so any future placeholder link stays safe by default, not just the ones special-cased.
- decorative icons paired with a visible label: give the `<svg>` `aria-hidden="true" focusable="false"`, so screen readers read only the visible label, never an untitled graphic alongside it.
- experience ordering: `Experience.astro` doesn't sort jobs, renders array as given — caller (index.astro) owns newest-first order. Matches Sidebar/Education's caller-owns-order convention, avoids duplicating sort policy inside the component.
- dark-mode color overrides: plain (unlayered) CSS custom-property rules in `global.css` beat Tailwind v4's `@theme`-layer vars regardless of source order — cascade layers always lose to unlayered CSS. So redefining `--color-navy-900` etc. under `[data-theme="dark"]` repaints every existing `text-navy-900`-style utility automatically, no need to touch component files or add `dark:` variants.
- browser storage calls (`localStorage` etc): wrap in try/catch — Safari private mode and blocked-storage settings throw on access, which would otherwise abort the whole script and break unrelated functionality (e.g. a click handler registered after the throwing line never attaches).
- bullet bold emphasis: achievement/project bullet strings support `**text**` markdown-lite for inline `<b>`, via `renderBullet()` in `src/components/bullet.ts`. Always escapes HTML first, then applies the bold replace — so the bold syntax can never be used to smuggle in arbitrary markup, even though current callers are dev-hardcoded data, not user input.
- `navy-500` can't be used for text: any blue light enough to read as visually distinct from `navy-700` fails WCAG AA (4.5:1) against `paper` — `navy-700` itself already sits near that boundary (5.96:1), leaving no room for a lighter-but-still-AA-passing shade. It's an inherent constraint of this palette/background pairing, not a one-off bug — use `navy-700` for any text that was tempted to reach for `navy-500`.
- `.ts`/`.js` files under `src/pages/` are treated as routes/endpoints by Astro, even test files — `astro build` crashes trying to render them. Page-level tests live in `test/pages/`, not next to the page.
- `astro preview` daemonizes itself independent of the shell job that launched it — killing the `&`-backgrounded PID does nothing, only `astro preview stop` actually stops it.
- CDP `Page.printToPDF` height measurement: don't measure `scrollHeight` with an arbitrarily tall emulated viewport if the page has `min-h-screen` (or any `100vh`-based CSS) — `vh` resolves against that viewport, so the "measurement" just echoes back whatever height you picked instead of the real content height. Use a deliberately tiny measurement viewport so real content always dominates.
- Summary moved from Sidebar to the main column (above Experience) post-implementation — the original [Resume Sidebar spec](../docs/specs/20260915211421_resume_sidebar.md)'s "6 sections including Summary" AC is now stale on this point; Sidebar is down to 5 sections (Education, Certificates, Languages, Frameworks, Selected Work), `summary` prop removed from its interface. Reason: narrative pitch read as buried/cramped at `text-2xs` in the narrow column — moved to the main column's `text-sm` body-prose scale where it belongs as the lead-in before Experience.
- Chrome's `Page.printToPDF` text layer orders by Y-position, not DOM order — a side-by-side flex row (e.g. Experience's title+company vs. location+dates columns) extracts row-by-row, interleaving the two columns instead of preserving source order. Fix is purely visual (stack into one column), never a DOM reorder — same markup either way.
- ATS-safe Experience layout lives only on the private `/ats` page (via `Experience.astro`'s `atsSafe` prop), not as a `print:`-media override on the public page — the public PDF is meant to visually match the site (a design/branding artifact), while `/ats` exists solely to be machine-parsed, so the two must be free to diverge rather than sharing one print stylesheet.
- CV language switch: both languages server-rendered + CSS-toggled instead of separate `/pl` routes — no reload/flash on toggle, and private `/ats` stays one URL instead of growing a `/ats/pl` sibling.
- `?lang=` query beats localStorage and is never persisted: PDF script must get deterministic language regardless of headless-Chrome profile state, and a shared `?lang=` link shouldn't overwrite the visitor's saved choice.
- per-block `lang` attr on each language wrapper instead of flipping `<html lang>` in JS: correct without JS, and hidden (`display:none`) block drops out of the a11y tree so screen readers only hit the visible language.
- CDP `Page.printToPDF` measurement width: measure `scrollHeight` at the content-box width (paper width minus side margins), not full paper width — print lays out in the narrower box, so wordier content (e.g. PL resume) rewraps taller than measured and spills onto a second page. Verify with `pdfinfo` page count, not the script log.
- base path: site is root user site (`niconisoria.github.io`), so no Astro `base` and no `withBase()` helper — CV prefix `/resume/` comes from folder layout (`src/pages/resume/`, `public/resume/`), hardcoded in hrefs. Re-adding `base` would double-prefix every CV URL.
